# Migrate a v1 installation to the proposed v2 layout

The proposed 2.0 layout moves canonical workflows from prompt files to
repository skills. It uses an ownership manifest at `.rpi/copilot/manifest.json`
and keeps recovery journals under ignored `.rpi/local/copilot/`. It does not
claim ownership from a matching filename. Existing
`.github/copilot-rpi-sync.json`, prompt files, chatmodes, project instructions,
VS Code JSONC settings and local extensions remain migration inputs until a
reviewed plan proves their exact bytes or owner changes.

## Choose and stage a package

Use Python 3.11+ and a verified local blueprint checkout. Replace the example
paths with actual absolute directories. Render into an empty staging directory;
do not point `render` at an adopter project.

```bash
selected_profile=cli
python3 "$source_dir/templates/scripts/rpi-distribution.py" validate --source "$source_dir"
python3 "$source_dir/templates/scripts/rpi-distribution.py" render \
  --source "$source_dir" --profile "$selected_profile" --target "$package_dir"
```

Set `selected_profile=agent-host` for VS Code Copilot Agent Host or
`selected_profile=vscode-local` for the optional Local prompt wrapper profile.
Choose only one profile per plan and keep the variable through check/detach. The
default package omits optional MCP and VS Code example configurations. The
resulting `package_dir` is the direct-install artifact: its
`.rpi/copilot-render.json` records the selected profile, component destinations
and SHA-256 hashes; `.rpi/copilot/runtime/` contains the standalone lifecycle
entrypoint and supporting scripts. Keep the whole directory. `plan` rejects a
missing, modified or mismatched receipt. A project already installed with a
different profile needs a reviewed detach or explicit migration plan before
the new profile is applied.

## Preview and apply

The package contains its own Python lifecycle runtime. Preview every action,
capability and conflict in a saved plan. An unchanged reviewed plan is required
for apply; changed inputs require a new plan.

```bash
python3 "$package_dir/.rpi/copilot/runtime/rpi-distribution.py" plan \
  --package "$package_dir" --target "$project_dir" \
  --profile "$selected_profile" \
  --output "$plan_file"
python3 "$package_dir/.rpi/copilot/runtime/rpi-distribution.py" apply \
  --plan "$plan_file"
python3 "$package_dir/.rpi/copilot/runtime/rpi-distribution.py" check \
  --package "$package_dir" --target "$project_dir" \
  --profile "$selected_profile"
```

`plan` may report unknown ownership or customized legacy bytes. Preserve those
bytes. Review the source and base before using the explicit `--adopt-exact`,
`--legacy-source` or `--legacy-base` options. Run `plan --help` for the current
contract. Do not remove old prompts or chatmodes by hand. They are retired only
when the lifecycle plan establishes ownership and selects their removal.
Copilot's manifest is separate from a cc-rpi `.rpi/manifest.json` in the same
project.

## Recovery and removal

An interrupted apply prints its journal path. Review it and run rollback;
rollback refuses to replace newer owner edits. Then create a fresh plan.

```bash
python3 "$package_dir/.rpi/copilot/runtime/rpi-distribution.py" rollback \
  --journal "$journal_file"
python3 "$package_dir/.rpi/copilot/runtime/rpi-distribution.py" detach \
  --package "$package_dir" --target "$project_dir" \
  --profile "$selected_profile" \
  --output "$detach_plan_file"
python3 "$package_dir/.rpi/copilot/runtime/rpi-distribution.py" apply \
  --plan "$detach_plan_file"
```

Detach preserves files with newer edits and project knowledge. The plan shows
retained and conflicting items before any write. Optional hooks, schedulers,
global settings and cloud runs have separate activation and removal procedures
in [native policy](../native-policy.md). Check the selected profile's actual
discovery with [compatibility fixtures](../compatibility.md) after migration.
